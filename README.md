# Network Request Inspector + Mock

Tampermonkey 用户脚本：拦截页面的 `fetch` / `XHR` 请求，在浮动面板中查看请求与响应，并复制为 Markdown、cURL、URL 或响应体，默认隐藏敏感信息；还可以按规则改写接口的返回（500、超时、断网、空列表、登录失效……），用来测前端的异常处理。

只改浏览器这一侧，不需要代理、不需要装证书，也不用动后端。

基于 Network Request Inspector（NRI）开发，Mock 部分来自本仓库原来的「接口报错模拟」脚本。

## 功能

- macOS 风格的检查器面板：上方请求列表，选中请求后下方显示详情区（响应体 / 响应头 / 请求），可随时关闭
- JSON 响应体以可折叠树展示，可切换为格式化源码；响应头与查询参数以键值表展示
- 在详情中查找文本，高亮全部命中并逐个跳转，折叠的 JSON 节点会自动展开
- 按 URL、成功 / 失败、响应类型筛选请求
- 多选请求后批量复制；右键菜单与完整的键盘操作
- 复制模式 Redacted / Raw，默认脱敏
- VS Code 与 macOS 两套配色，各有深色与浅色变体
- 偏好设置在所有网站间同步
- Mock：从抓到的请求一键建规则，改状态码、响应体、延迟，拦截、放行或挂起请求
- 刷新页面后请求列表仍在
- 在线安装并自动更新正式版，可选择接收测试版；设置中显示当前版本，可随时手动检查更新

## 安装

需要 Tampermonkey `>= 5.4`。Chrome 还要在「扩展程序 → Tampermonkey → 详情」里打开「允许运行用户脚本」。在装有 Tampermonkey 的浏览器中打开以下地址即可安装：

```text
https://raw.githubusercontent.com/sleepray/Web-api-mock/main/dist/prod/network-request-inspector.user.js
```

> **装过旧版「接口报错模拟」脚本的**：先在 Tampermonkey 里删掉它，再安装上面的脚本。旧脚本的规则会在你打开对应网站时自动迁移过来。两个脚本同时装着时，面板会弹出提示。

- Tampermonkey 会按自身的检查周期自动安装新的正式版，不会自动安装测试版。
- 点击工具栏右端的齿轮打开设置，**Updates** 一栏显示完整版本号（如 `v0.3.0`、`v0.3.0-beta.1`）。点击 **Check for Updates** 检查是否有更新的版本，有则显示 **Install vX.Y.Z** 链接，点击后由 Tampermonkey 完成安装；没有则短暂显示 **Up to date**。检查失败时显示 **Update check failed**，悬停可查看原因。
- 有可安装的新版本时，齿轮右上角显示一个小圆点。
- 更新后第一次打开面板（在任意网站）时显示 **What's New**，列出从上一个版本到当前版本之间每个版本的变更，可跨多个版本；正式版的说明已包含其测试版的内容，因此不再重复列出这些测试版。点 **Done** 或按 `Esc` 返回请求列表。之后可在设置 **Updates** 一栏的 **What's New** 中查看所有版本的变更。首次安装时不显示。
- **Beta Versions** 开关决定是否接收测试版，默认关闭，所有网站共用这一设置：
  - 打开后立即检查一次，此后每天自动检查一次。发现新版本时在页面上弹出提示，齿轮上显示圆点；没有新版本或检查失败时不打扰。
  - 测试版的检查同样包含正式版，因此只需安装比当前版本更新的那个。
  - 关闭后不再提示新的测试版；已安装的测试版会在下一个更高的正式版发布后，由 Tampermonkey 自动升级。
- 首次安装时，Tampermonkey 会请你确认脚本访问 `raw.githubusercontent.com` 的权限，这是检查更新所必需的。
- GitHub 的文件地址有几分钟缓存，刚发布的版本可能要等一会儿才查得到。

## 使用

点击页面右下角的 **NRI** 按钮，或在页面任意位置按 `H`，即可打开或隐藏面板。面板打开时按钮变为向下箭头，再点一次即可收起；悬停时提示点击的作用、快捷键与请求数。有请求失败时按钮会变红。

### 请求列表

- 每行显示状态（绿色 2xx、蓝色 3xx、红色 4xx / 5xx / 网络错误、橙色进行中）、方法、路径、耗时与开始时间。返回被 Mock 规则改过的请求带 **MOCK** 标记。
- 刷新页面后列表仍在：刷新前的请求排在 **Before reload** 分隔线下面，照样可以查看、复制和建规则。列表在离开页面时存进当前标签页的 `sessionStorage`，关掉标签页或清空请求后就不再保留；存之前会把请求头、URL 参数、请求体和响应头脱敏，响应体保留原文（建规则要用），总量超过约 100 万字符时较早请求只留请求、不留响应体。
- 点击某一行查看详情，方向键切换请求时详情随之更新。没有选中请求时不显示详情区，列表占满面板。
- 多选的用法与 macOS 表格一致：`⌘` 点击切换选中，`Shift` 点击或 `Shift` + 方向键连续选择，`⌘A` 全选可见请求。详情区显示最后点击的请求；筛选后，被隐藏的行会自动移出选择，因此复制时只包含可见的请求。
- 默认不记录常见静态资源（JavaScript、CSS、图片、字体）。列表最多保留 80 条请求，复制时过长的响应体会被截断。

### 详情区

- 顶部显示状态码及原因短语（如 `404 Not Found`）、耗时、响应大小、开始时间与来源（Fetch / XHR），下方是方法与完整 URL。
- **Body** 显示响应体，**Headers** 显示响应头，**Request** 显示查询参数、请求头与请求体；`</>` 按钮在 JSON 树与格式化源码之间切换。
- 提供以下复制按钮：复制请求与响应（Markdown）、复制响应体、复制为 cURL。
- 放大镜按钮（或焦点在详情区时按 `⌘F`）打开查找栏，在当前标签的内容中查找文本，不区分大小写：所有命中以黄色高亮，当前命中为橙色并滚动到可见位置，计数显示「当前 / 总数」。`Return` / `⇧Return` 或两侧箭头跳到下一个 / 上一个，首尾循环；`Esc` 关闭查找栏。JSON 树视图按完整数据查找，跳转到折叠节点或未加载的大数组条目时会自动展开。切换请求或标签时保留查找词并重新查找，最多统计 1000 个命中。
- 点击右上角的 `×` 或按 `Esc` 关闭详情区，同时取消选中；再点击任意一行即重新打开。
- 拖动详情区上方的分隔线可调整详情高度；拖动面板左侧或顶部边缘可调整面板尺寸。

### 筛选

- **Filter URL**：按 URL 筛选。
- **All | Failed | Mocked**：Failed 只显示 4xx、5xx 与网络错误；Mocked 只显示返回被 Mock 规则改过的请求。
- **类型标签**（JSON、Doc、Text、JS、CSS、Img、Media、Font、Other）：与 DevTools 的 Network 面板类似，点击只显示该类型，`⌘` 点击可多选，**All** 恢复全部。类型优先按响应体能否解析为 JSON 判断，其次看响应的 `Content-Type`；没有可用类型时（进行中、失败、`application/octet-stream`）按 URL 扩展名判断，仍无法判断则归为 Other。没有对应请求的类型标签会变暗。
- 计数器显示「匹配数 / 总数」。

### 复制与脱敏

- **Redacted | Raw** 默认为 Redacted，影响列表、详情以及所有复制方式（Markdown、cURL、URL、响应体）。
- Redacted 模式会隐藏：认证类请求头、Cookie、API Key、敏感 URL 参数，以及 JSON 和 URL 编码表单中名为 token、secret、password、key、session 等的字段。纯文本、HTML 与 XML 不做改动。
- Raw 模式显示捕获到的原始内容。

### 右键菜单

- 在某一行上右键：**Mock This Request**（已有规则时为 **Edit Mock Rule**）、复制请求与响应、复制为 cURL、复制 URL、复制响应体、复制全部可见请求、清空请求。
- 在多选范围内右键：按列表顺序复制所选的 N 个请求（Markdown、cURL 或 URL）。
- 在未选中的行上右键，会先只选中该行。

### Mock

工具栏左侧的 **Requests | Rules** 在请求列表和规则列表之间切换，**Rules** 上的数字是这个网站的规则条数（有规则生效时为红色）。

**建规则**

1. 在页面上正常操作一下，让要测的接口发一次请求。
2. 在请求列表里选中它，看一眼详情确认是这个接口。
3. 点详情区的魔杖按钮，或右键选 **Mock This Request**。规则会带上这个请求的方法、路径，以及它真实返回的状态码和响应体，并切到规则列表定位到它。刚建好的规则返回的和原来一样，在它上面改。
4. 改状态码或响应体，或者点预设；回到页面再触发一次这个接口，看前端怎么表现。

已经有规则管着的请求，魔杖按钮变为橙色，右键菜单变为 **Edit Mock Rule**，点了跳到那条规则，不会重复建。也可以在规则列表点 **+ New Rule** 手动新建。

**规则能设什么**

- **匹配**：请求方法 + URL 里包含的一段文字；以 `re:` 开头的按正则匹配。从请求建的规则用路径匹配，不带查询参数。
- **Respond**：状态码（`0` 表示网络错误）和模式。
- **Delay**：等多少毫秒再返回。
- **Max hits**：最多命中几次，之后放行；比如填 1 可以测「第一次失败、重试成功」。`0` 不限。命中次数显示在右侧，**Reset** 清零。
- **响应体**：输入时自动补上配对的引号和括号，回车保持缩进，`Tab` 输入两个空格。像 JSON 却不合法时提示具体错误，旁边的 **Auto-fix** 会补上缺的引号、逗号、括号，去掉多余的逗号，把单引号和中文引号换成双引号再排版，改完说明修了几处，可以 **Undo**。右上角的 **Format** 重新排版。

规则里的响应体始终显示和保存原文，不受 Redacted 模式影响——页面要拿到的就是原文。

**三种模式**

| 模式 | 请求到不到服务器 | 用途 |
|---|---|---|
| **Block**（默认） | 不到 | 最常用。后端什么都没发生，安全 |
| **Pass through** | **到，并且真的执行** | 模拟「服务端已处理，前端却收到失败」；详情区能看到服务器真正的返回 |
| **Hang** | 不到，也一直不返回 | 看加载状态、测前端超时；页面取消请求或 XHR 设了超时会照常触发 |

> **Pass through 要小心**：请求会真的发到服务器并执行，页面只是看到被改过的返回。下单、支付、审批这类接口照样会真的生效。

**预设**

| 按钮 | 效果 |
|---|---|
| 500 / 502 / 504 / 401 / 403 | 设成这个状态码，响应体换成 `{code, message}` 报错内容（原响应体的 `code` 是字符串时也给字符串） |
| Offline | 网络错误，请求发不出去 |
| Slow 3s | 其它不变，等 3 秒再返回 |
| Empty list | 返回 200，把响应体里两层以内的列表清空、`total` / `count` 一类归零 |
| Never respond | 切换到 Hang |
| ↺ Reset | 回到真实返回：状态码和响应体恢复，模式回到 Block，延迟清零 |

**别忘了关**

规则按网站保存在 `localStorage`，刷新后仍然生效，同一网站的其它标签页同步生效。忘了关的话，过几天打开页面看到接口报错，很容易当成真的 bug。为此：

- 有规则生效时，角标上显示 **Mock N**，面板收起贴边时露出的那一截变红；悬停提示里也写着规则条数。
- 规则列表顶部有 **Pause All**，临时停用全部规则，规则本身保留；暂停时角标显示 **Paused**。
- **Clear All** 删除全部规则，要点两次确认。

在规则列表里，面板的快捷键（`⌘K`、`⌘F`、方向键等）不生效，按键都留给输入框；`Esc` 先离开输入框，再按一次回到请求列表。

### 设置

工具栏右端的齿轮打开设置浮层，点击浮层外部或按 `Esc` 关闭。浮层分为三栏：

- **Appearance**：配色（**Style**）、明暗主题（**Theme**：跟随系统、浅色、深色）与界面语言（**Language**：自动、English、中文）。语言默认「自动」，浏览器首选语言是中文时显示中文，否则显示英文；切换后立即生效，不用刷新页面。复制出去的 Markdown、cURL 始终是英文。
- **Keyboard**：显示 / 隐藏面板的快捷键，见下文「快捷键」。
- **Updates**：当前版本、测试版开关与检查更新，见上文「安装」。

### 外观

两套配色各有深色与浅色变体：

- **VS Code**（默认）：VS Code 2026 的不透明背景与文字颜色，选中色为经典的 `#007ACC`。
- **macOS**：半透明毛玻璃面板，使用 Apple 系统色（选中色 `#0A84FF` / `#007AFF`）与 0.5px 细分隔线。

面板始终使用自带的界面字体与等宽字体，不受宿主页面样式影响。

### 补充说明

- **悬停说明**：按钮、分段控件和筛选标签停留约 0.4 秒显示功能说明；请求行停留约 1.5 秒显示完整 URL。
- **跨站同步**：界面语言、主题、配色、面板尺寸、面板垂直位置、详情高度、复制模式、显示 / 隐藏快捷键与测试版开关保存在 Tampermonkey 的全局存储中，在所有网站间同步；面板的打开 / 隐藏状态按网站分别保存。
- **单实例**：脚本只在顶层窗口运行，每个页面只会出现一个 NRI 按钮，iframe 内发出的请求不会被记录，也不会被 Mock 规则改写。同时安装了正式版与开发代理时，只有先加载的那个会启动。
- **Mock 管不到的**：只对页面里用 `fetch` 和 `XMLHttpRequest` 发的请求生效。页面跳转、表单提交、链接触发的文件下载、WebSocket、Service Worker 里发出的请求改不了。
- **数据去向**：脚本不上传任何数据。唯一的对外请求是检查更新时读取本仓库里的版本文件。

- pnpm `>= 12`

### 常用命令

| 命令 | 说明 |
|------|------|
| `pnpm install` | 安装依赖 |
| `pnpm dev` | 启动本地脚本服务并监听构建 |

| `pnpm test` | 运行单元测试（Vitest） |

### 使用开发代理调试

开发时只需在 Tampermonkey 中安装一次代理脚本，之后修改代码不用重新安装。

1. 运行 `pnpm dev`，确认控制台输出 `[nri-dev-server] listening on http://localhost:3010` 以及构建成功的信息。
2. 在 Tampermonkey 中安装 `dist/dev/dev-proxy.user.js`。这是开发时唯一需要安装的脚本。
3. 刷新任意页面。
4. 之后每次保存代码都会自动重新构建，强制刷新页面（`⌘⇧R`）即可加载最新的主脚本。

控制台日志：

| 日志 | 含义 |
|------|------|
| `[nri-dev] Launch successful!` | 代理已获取并运行主脚本 |
| `[NRI] Network Request Inspector loaded` | 主脚本初始化完成 |

如果代理成功但主脚本没有加载，依次检查：端口是否正确；`http://localhost:<端口>/network-request-inspector.user.js` 是否返回 200；控制台是否有注入报错。

### 端口配置

本地脚本服务默认使用 `3010` 端口，可通过 `NRI_DEV_PORT` 修改（也可以用 `PORT`，优先级更低）：

```bash
cp .env.example .env   # 在 .env 中设置 NRI_DEV_PORT=3020
pnpm dev
# 或者直接覆盖
NRI_DEV_PORT=3020 pnpm dev
```

配置的优先级从高到低：命令行 / 系统环境变量 > `.env.local` > `.env` > 默认值 `3010`。两个 `.env` 文件都不入库。

端口会写进代理脚本，所以修改端口后需要重新构建，并重新安装 `dist/dev/dev-proxy.user.js`。

## 构建与发布

### 生产构建

```bash
pnpm build
# → dist/prod/network-request-inspector.user.js   完整脚本
# → dist/prod/network-request-inspector.meta.js   仅含脚本头，供 Tampermonkey 检查更新
# → dist/prod/update.json                         只有版本号，供面板里的 Check for Updates 读取
```

`dist/prod/` 入库：安装和更新都直接读 GitHub 上这几个文件。`dist/dev/` 不入库。

### 版本号

`package.json` 中的 `version` 会原样作为脚本的 `@version`，只允许以下两种格式，否则构建失败：

| 格式 | 示例 | 推到哪个分支 |
|------|------|------|
| `X.Y.Z` | `0.4.0` | `main`（正式版）与 `beta`（测试版） |
| `X.Y.Z-(alpha\|beta\|rc).N` | `0.4.1-beta.1` | 只推 `beta` |

这是 Tampermonkey 版本比较结果与语义化版本一致的范围：`beta.9 < beta.10`、`alpha < beta < rc`、`0.3.0-rc.1 < 0.3.0`。每个版本号（包括测试版）都是唯一的，面板直接显示完整版本号；开发构建显示为 `vX.Y.Z (dev)`，并且不提供检查更新。

### 发布

两个更新通道对应两个分支：正式版读 `main` 分支上的 `dist/prod/`，测试版（设置里打开 **Beta Versions** 后）读 `beta` 分支上的。

1. 递增 `package.json` 中的版本号；
2. 把 `CHANGELOG.md` 中的 `## [Unreleased]` 整理后改为 `## [X.Y.Z] - YYYY-MM-DD`；
3. `pnpm test`、`pnpm typecheck` 通过后运行 `pnpm build`，把 `dist/prod/` 连同改动一起提交；
4. 推送：

```bash
git push origin main main:beta   # 正式版：两个分支一起推
git push origin HEAD:beta        # 测试版：只推 beta
```

已发布的版本号不复用，每次发布都需要一个新的版本号。
